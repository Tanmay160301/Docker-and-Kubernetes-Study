Bhai, **`docker logs`** ani **`docker inspect`** he donhi troubleshooting sathi vapartat, pan te completely vegli information detat.

Simple rule:

> **`docker logs` = Application kay bolat ahe te bagh**
>
> **`docker inspect` = Docker la tya container baddal kay mahit ahe te bagh**

---

# 1. docker logs

Command:

```bash
docker logs <container-id>
```

He container madhlya application cha:

```text
stdout
stderr
```

output dakhavto.

Example:

```text
Application Started

Connected to Database

Error: Connection Timeout
```

---

## Use Case

Container running ahe.

Pan application kaam kart nahi.

Tyaveli:

```bash
docker logs my-container
```

---

## Interview Definition

> "docker logs is used to view the runtime output generated by the application running inside the container."

---

# 2. docker inspect

Command:

```bash
docker inspect <container-id>
```

He JSON format madhye detailed metadata dakhavto.

Example:

```json
{
  "Id": "...",
  "Image": "nginx",
  "State": {
    "Running": true
  },
  "NetworkSettings": {
    "IPAddress": "172.17.0.2"
  }
}
```

---

## Kay Kay Baghu Shakto?

### Container IP

```bash
docker inspect my-container
```

Output:

```text
172.17.0.2
```

---

### Mounted Volumes

```text
/app/data
```

kuthe mount zala ahe.

---

### Environment Variables

```text
DB_HOST=mysql
DB_PORT=3306
```

---

### Image Information

```text
nginx:latest
```

---

### Port Mapping

```text
80 -> 8080
```

---

### Container State

```text
Running

Exited

Restarting
```

# Real Troubleshooting Example

### Scenario 1

Application error det ahe.

Use:

```bash
docker logs my-container
```

Output:

```text
Database Authentication Failed
```

Problem application madhye.

---

### Scenario 2

Application connect hot nahi.

Use:

```bash
docker inspect my-container
```

Output:

```text
IPAddress:
172.17.0.2
```

kiva

```text
Port Mapping Missing
```

Problem container configuration madhye.

---

# Quick Comparison

| Command          | Purpose                               |
| ---------------- | ------------------------------------- |
| `docker logs`    | Application output bagh               |
| `docker inspect` | Container metadata/configuration bagh |

# Interview Answer

> "docker logs displays the stdout and stderr output generated by the application running inside a container. docker inspect provides detailed metadata about the container, including its configuration, network settings, mounted volumes, environment variables, image information, and runtime state."

---

## One-Line Interview Version

> **"`docker logs` helps diagnose application-level issues, while `docker inspect` helps diagnose container configuration and runtime issues."** ✅

### Follow-up Interview Tip

Jar interviewer vicharla:

> "Container is running but application is not reachable. Which command would you use first?"

Good answer:

> **"I would typically start with `docker logs` to check for application errors, and then use `docker inspect` to verify networking, port mappings, environment variables, and container configuration."** ✅
