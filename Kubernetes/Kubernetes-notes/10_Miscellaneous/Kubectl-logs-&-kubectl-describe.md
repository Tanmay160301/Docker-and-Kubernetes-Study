Bhai, interview madhye ha question khup common ahe.

Simple rule:

> **`kubectl logs` = Application ne kay print kela te baghaycha**
>
> **`kubectl describe` = Kubernetes la tya Pod baddal kay mahit ahe te baghaycha**

---

# 1. kubectl logs

Command:

```bash
kubectl logs my-pod
```

He container cha stdout/stderr output dakhavto.

Example:

Application:

```java
System.out.println("Application Started");
```

kiva

```javascript
console.log("Connected to DB");
```

Logs:

```text
Application Started

Connected to DB

Error: Database connection failed
```

---

## Use Case

Samja Pod Running ahe pan application error det ahe.

```text
Pod = Running

Application = Failing
```

Tyaveli:

```bash
kubectl logs my-pod
```

baghto.

---

## Interview Answer

> "kubectl logs is used to view the application logs generated by the container running inside the Pod."

---

# 2. kubectl describe pod

Command:

```bash
kubectl describe pod my-pod
```

He Kubernetes metadata ani events dakhavto.

Example output madhye:

```text
Name: my-pod

Node: worker-node-1

IP: 10.1.0.5

Image:
my-app:v1
```

---

### Events Section

Khup important.

Example:

```text
FailedScheduling

ImagePullBackOff

OOMKilled

CrashLoopBackOff
```

---

## Use Case

Pod startach hot nahi.

```text
STATUS:
ImagePullBackOff
```

Tyaveli:

```bash
kubectl describe pod my-pod
```

bagh.

Events madhye exact reason disel.

```text
Pod = Running
```

Command:

```bash
kubectl logs my-pod
```


# Quick Comparison

| Command                | Purpose                                    |
| ---------------------- | ------------------------------------------ |
| `kubectl logs pod`     | Application logs                           |
| `kubectl describe pod` | Pod details, configuration, status, events |

# Interview Answer

> "kubectl logs is used to view the stdout and stderr output generated by the application running inside a container. kubectl describe pod provides detailed information about the Pod, including its configuration, status, node assignment, conditions, and recent events such as scheduling failures, image pull errors, or restarts. During troubleshooting, I typically use describe to understand Kubernetes-level issues and logs to investigate application-level issues."

### One-Line Interview Version

> **"`kubectl describe pod` helps diagnose Kubernetes issues, while `kubectl logs` helps diagnose application issues."** ✅
